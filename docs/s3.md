# Setup Guide: S3 Storage Backend

This guide outlines how to configure S3 and initialize the `S3Storage` backend in your client-side application.

---

## 1. CORS Configuration

Since the `S3Storage` client runs entirely in the browser, your S3 bucket must have a Cross-Origin Resource Sharing (CORS) policy configured to allow requests from your web app's origin.

Here is a recommended CORS configuration (JSON):

```json
[
  {
    "AllowedHeaders": ["*"],
    "AllowedMethods": ["GET", "PUT", "POST", "DELETE", "HEAD"],
    "AllowedOrigins": ["http://localhost:5173", "https://your-app.com"],
    "ExposeHeaders": ["ETag", "Content-Length"]
  }
]
```

---

## 2. Recommended IAM Policy (Least Privilege)

If you are using AWS IAM credentials, apply a policy to the IAM user or role restricting them only to the necessary operations on the specific bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": [
        "s3:ListBucket",
        "s3:GetBucketLocation"
      ],
      "Resource": "arn:aws:s3:::your-bucket-name"
    },
    {
      "Effect": "Allow",
      "Action": [
        "s3:PutObject",
        "s3:GetObject",
        "s3:DeleteObject"
      ],
      "Resource": "arn:aws:s3:::your-bucket-name/*"
    }
  ]
}
```

---

## 3. Initialization in Client-Side JS

To initialize the backend, import `S3Storage` and pass configuration parameters:

```typescript
import { S3Storage } from 'stratus-base';

const backend = new S3Storage({
  accessKeyId: 'YOUR_ACCESS_KEY_ID',
  secretAccessKey: 'YOUR_SECRET_ACCESS_KEY',
  region: 'us-east-1',
  bucket: 'your-bucket-name',
  // Optional endpoint configuration for S3-compatible providers (Cloudflare R2, MinIO, etc.)
  endpoint: 'https://<account-id>.r2.cloudflarestorage.com',
  forcePathStyle: false
});

if (await backend.isConfigured()) {
  console.log('S3 Storage backend is configured and ready!');
}
```
